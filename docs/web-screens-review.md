# مراجعة وتنظيم شاشات الويب

أُجريت هذه المراجعة في 26 سبتمبر 2026 على نسخة التجربة المحلية. تشمل شاشات الويب، ولا تشمل إعادة تصميم شاشات JavaFX.

## التنظيم النهائي

| الشاشة | التنظيم |
| --- | --- |
| تسجيل الدخول | بطاقة واحدة بعناوين واضحة ومدخلات متتابعة، مع إبقاء بيانات السنتر الاختيارية منفصلة عن بيانات الدخول. |
| التركيب الأول | مراجعة النموذج في المصدر وترتيب بطاقته؛ لم يُنشأ حساب جديد أو يُعد تنفيذ التركيب على قاعدة التجربة المستخدمة. |
| اليوم | جدول اليوم منفصل عن فتح الحصص وإغلاقها. |
| الحضور | بوابة إدخال الحصة والباركود، ثم نتيجة العملية، ثم سجل الحضور. |
| الخزينة | التحصيل، تسجيل المصروف، وحركة اليوم في تبويبات منفصلة. |
| الطلاب | قائمة وبحث، نموذج إضافة وتعديل، اشتراكات، وسجل حركات. التفاصيل لا تُفتح قبل اختيار طالب. |
| المجموعات | قائمة، نموذج مستقل، وكشف المجموعة المختارة. |
| المال | كشف المصروفات مستقل عن مستحقات المعلمين. المرشحات والإجماليات والتصدير قريبة من الجدول الخاص بها. |
| الإدارة | الإعدادات، المعلمون، المستخدمون، وسجل المراقبة. للمعلمين والمستخدمين قوائم مستقلة عن النماذج، وللإعدادات بيانات عامة ونسخ احتياطي ورسائل. |
| التنبيهات | الصندوق، إعدادات الفحص، القواعد، إعداد رسائل أولياء الأمور، وسجل الإرسال. تعديل القاعدة يخفي القائمة حتى الحفظ أو الإلغاء. |
| التقارير | بطاقة لكل تقرير مع وصف لغرضه، ومرشح فترة مستقل. التقارير المالية لا تظهر للسكرتير. |

## قواعد العرض المشتركة

- عنوان ووصف قصير للمهمة، ثم مرشحات أو نموذج، ثم المحتوى المطلوب فقط.
- لكل حقل عنوان فوقه، مع شبكة تتكيف مع العرض، وصف واضح لأزرار الحفظ والرجوع.
- زر العودة للقائمة لا يمسح المسودة. المسودات غير المحفوظة للإعدادات وصلاحية المستخدم لا تُستبدل عند العودة من شاشة أخرى.
- الجداول تتمرر أفقياً داخل إطارها، دون تمديد الصفحة كلها. أزرار الحذف لها لون مختلف عن التعديل.
- الرسائل والنتائج تظهر في القسم الذي يخصها، بما فيها حفظ إعدادات فحص التنبيهات وأخطاء سجل الإرسال.
- تسجيل الخروج ينظف المسودات والجداول والتفاصيل المفتوحة ويعيد التبويبات إلى بدايتها، قبل دخول حساب آخر.
- مفاتيح النصوص العربية والإنجليزية في الحزمتين، والتخطيط يستخدم خصائص اتجاه محايدة ومقاسات حول النص بوحدة em.

## التحقق

- نجح بناء الوحدات ثم بناء النسخة النهائية للويب.
- نجحت اختبارات center-web البالغ عددها 104، واختبارات MessageBundleTest الستة، دون فشل أو أخطاء أو اختبارات متروكة.
- نجح فحص JavaScript وgit diff --check.
- فُحصت بنية HTML: 265 معرّفاً فريداً و24 نموذجاً، دون نماذج متداخلة أو مراجع تبويبات وعناوين حقول مكسورة.
- روجعت الشاشات الرئيسية التسع وتبويباتها في المتصفح، إضافة إلى نماذج الطالب والمعلم والمستخدم وكشف المجموعة ومحرر قاعدة التنبيه.
- فُحص احتواء الشاشات الرئيسية التسع بعرض 1440 وبعرض 390؛ لم يتجاوز عرض الصفحة عرض المتصفح. أعيد مقاس المتصفح إلى وضعه الطبيعي بعد الاختبار.
- ثبت بقاء مسودة إعدادات عند الخروج إلى التقارير ثم العودة، وبقاء صلاحية السكرتير المختارة في نموذج المستخدم بعد العودة للإدارة.
- بعد عرض تفاصيل طالب بالمدير ثم تسجيل الخروج والدخول بالسكرتير، ظهرت قائمة الطلاب من البداية وكانت تبويبات التفاصيل غير متاحة حتى اختيار طالب جديد.
- لم تظهر أخطاء JavaScript في سجل المتصفح النهائي.

العدد 579 في تقرير التجربة المحلية السابق يخص الجولة السابقة. لم تُعد تلك المجموعة كاملة لهذه التغييرات في العرض؛ هذه الجولة تضم 110 اختبارات آلية إضافة إلى التحقق التفاعلي المذكور أعلاه. لم تُختبر طابعة أو قارئ باركود فعليان في هذه المراجعة.
